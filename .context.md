# Supplier Report App (FastAPI + React)

## Project Overview
A full-stack application for managing supplier reports and warehouse data with data visualization and analysis capabilities.

**Tech Stack:**
- **Backend:** FastAPI (Python)
- **Frontend:** React + Vite
- **Data Management:** JSON mapping files, CSV uploads

---

## Backend Structure (`/backend`)

### Core Components
- **`main.py`** - FastAPI application entry point
- **`requirements.txt`** - Python dependencies
- **`split_mappings.py`** - Utility for handling data mappings

### API Layer (`/api`)
- **`routes.py`** - API endpoints for data operations

### Core Utilities (`/core`)
- **`mapping_utils.py`** - Utilities for data mapping transformations
- **`utils.py`** - General utility functions

### Data Configuration
- **`mapping.json`** - Field mappings for data normalization
- **`bond_mapping.json`** - Bond/relationship mappings
- **`warehouse_mapping.json`** - Warehouse location mappings

### Services (`/services`)
- **`registry.py`** - Service registry and dependency management
- **`store.py`** - Data storage operations
- **`reports/`** - Report generation modules
  - `base.py` - Base report class
  - `combined_shopwise.py` - Combined shop-level analysis
  - `cumulative_shopwise.py` - Cumulative shop analytics
  - `cumulative_warehouse.py` - Cumulative warehouse analytics
  - `daily_secondary_sales.py` - Daily secondary sales reports
  - `daily_warehouse_offtake.py` - Daily warehouse offtake tracking
  - `month_comparative.py` - Monthly comparative analysis
  - `monthly_stock_sales.py` - Monthly stock and sales data
  - `shopwise.py` - Shop-level reports
  - `warehouse.py` - Warehouse-level reports

## Key Features

### Data Management
- Upload and process supplier data from multiple sources
- Map data fields to standardized formats
- Track warehouse and shop-level metrics

### Reporting
- Multiple report types: daily, cumulative, comparative, shop-wise, warehouse-wise
- Monthly and periodic analysis
- Data cleanup and consolidation

### UI Features
- Status calendar for tracking data updates
- File upload modals for different data types
- Report visualization and export capabilities
- Sidebar navigation

---

## Communication Flow
1. **Frontend** sends requests via `api.js` to FastAPI backend
2. **Backend** processes requests through API routes
3. **Services** handle business logic and report generation
4. **Data** is normalized using mapping utilities
5. **Response** is sent back to frontend for display

---

## Data Files
- `mapping.json` - Field name transformations and standardization
- `warehouse_mapping.json` - Warehouse location and hierarchy
- `bond_mapping.json` - Entity relationship mappings

---

## Development Notes
- Backend runs on FastAPI default (typically port 8000)
- Frontend uses Vite for fast HMR during development
- Both frontend and backend use JSON-based configuration
- Modular report architecture allows easy addition of new report types
